1. What the system does

AIMF Secure Forms

Builds reusable WordPress forms, validates submissions, stores entries, sends notifications, and provides privacy controls.

Cloudflare Turnstile

Runs a browser challenge, issues a short-lived single-use token, and validates that token through Cloudflare Siteverify.

Content Security Policy

Controls which scripts, connections, frames, styles, and fonts the browser may load.

YubiKey PIV 9D

Holds the RSA private key used to decrypt configuration and submission exports. The private key never leaves the YubiKey.

Submission security sequence

  1. WordPress verifies the CSRF nonce and honeypot.
  2. Per-IP and global rate limits are enforced.
  3. The lazy-fetched, single-use JavaScript token is verified.
  4. The server-signed form timestamp is validated.
  5. Configured fields are sanitized and validated.
  6. Turnstile is verified server-side and checked for the expected hostname and action.
  7. Optional Akismet analysis runs.
  8. The submission is stored and the notification is sent.

2. Install or update the plugin

  1. Back up the WordPress database.
  2. Open Plugins → Add Plugin → Upload Plugin.
  3. Select aimf-secure-forms.zip.
  4. Select Install Now.
  5. For an update, select Replace current with uploaded.
  6. Confirm AIMF Secure Forms is active and reports version 1.1.0 or later.
Preserved during replacement: forms, settings, CAPTCHA keys, and stored submissions remain in WordPress. Do not delete the plugin when the goal is only to update it.

Enable GitHub update notifications

The plugin checks published GitHub Releases. A normal source push does not create a WordPress update notice. Each update needs a higher plugin version, matching tag, published release, and an attached asset named aimf-secure-forms.zip.

Because the repository is private, create a fine-grained GitHub token restricted to this repository with read-only Contents access. Add it above the stop-editing line in wp-config.php:

define( 'AIMF_SCF_GITHUB_TOKEN', 'PASTE_READ_ONLY_TOKEN_HERE' );
Never commit the token or enter it in plugin settings, form configuration, screenshots, or support messages. If the repository becomes public, remove this constant; public release checks need no token.

WordPress caches release metadata for six hours. Use Dashboard → Updates → Check again to request an immediate refresh.

3. Create and configure a form

  1. Open AIMF Forms → Form Builder.
  2. Select Add New Form or edit an existing form.
  3. Add single-line, email, paragraph, dropdown, multiple-choice, checkbox, or number fields.
  4. Select each field to configure its label, options, placeholder, description, and required state.
  5. Set the notification email, success message, and submit button text.
  6. Save and copy the generated shortcode.

Default form shortcode

[aimf_form id="1"]

Custom form shortcode

[aimf_form id="2"]
Never request passwords, private keys, recovery codes, payment-card data, or detailed incident evidence through a general web form.

4. Add the form to Divi

  1. Open the page in Divi Builder.
  2. Add a Code Module where the form should appear.
  3. Paste only the selected shortcode.
  4. Save the module and page.
  5. Exit Visual Builder and test the published page.
[aimf_form id="1"]

The form fills the available Divi module width. Set overall width through the Divi row and column settings.

5. Configure Cloudflare Turnstile

Create the widget

  1. Sign in to the Cloudflare dashboard.
  2. Open Turnstile and select Add widget.
  3. Use a recognizable widget name such as aimfsecurity.com Secure Forms.
  4. Add hostname aimfsecurity.com. Do not include a scheme, path, port, or wildcard.
  5. Select Managed widget mode.
  6. Create the widget and copy its site key and secret key.

Configure WordPress

  1. Open AIMF Forms → Settings.
  2. Paste the public key into Turnstile Site Key.
  3. Paste the secret into Turnstile Secret Key.
  4. Leave reCAPTCHA and hCaptcha blank when Turnstile is used.
  5. Save settings.
Secret handling: never place the Turnstile secret in Divi, a shortcode, JavaScript, source control, screenshots, or configuration exports.

The widget sends action aimf_secure_form and form metadata such as form_1. The server validates the token, action, and hostname.

6. Configure the live Content Security Policy

On AIMF Security, the CSP is defined in the custom block at the top of .htaccess, above the WordPress-managed section.

Required block

# === OVERRIDE MODSECURITY CSP - ALLOW ANALYTICS AND TURNSTILE ===
<IfModule mod_headers.c>
    Header unset Content-Security-Policy
    Header always unset Content-Security-Policy
    Header always set Content-Security-Policy "default-src 'self'; script-src 'self' 'unsafe-inline' 'unsafe-eval' https://*.googletagmanager.com https://*.google-analytics.com https://challenges.cloudflare.com; connect-src 'self' https://*.google-analytics.com https://*.analytics.google.com https://*.googletagmanager.com https://challenges.cloudflare.com; frame-src 'self' https://challenges.cloudflare.com; img-src 'self' data: https:; style-src 'self' 'unsafe-inline' https://fonts.googleapis.com; font-src 'self' data: https://fonts.gstatic.com; frame-ancestors 'self';"
</IfModule>
# === END CSP OVERRIDE ===

Safe editing process

  1. Download a backup of .htaccess.
  2. Replace only the existing custom CSP block.
  3. Do not edit inside # BEGIN WordPress or Newfold-managed blocks.
  4. Save and immediately confirm the homepage and contact page still load.
  5. Confirm only one CSP response header is returned.
curl -sI https://aimfsecurity.com/contact/ \
  | grep -ic '^content-security-policy:'

Expected result: 1.

Do not add data: to script-src. The plugin uses data-noptimize and data-cfasync="false" to avoid optimizer rewrites instead of weakening CSP.

7. Clear optimization and platform caches

Autoptimize

  1. Open Settings → Autoptimize → JS, CSS & HTML.
  2. Keep Optimize JavaScript Code enabled.
  3. Keep Do not aggregate but defer enabled.
  4. Ensure Also defer inline JS is disabled.
  5. Select Save Changes and Empty Cache.

Divi

  1. Open Divi → Theme Options → Builder → Advanced.
  2. Find Static CSS File Generation.
  3. Select Clear.
  4. Save changes.

Hosting and Cloudflare

  1. Purge the Bluehost page cache.
  2. Open Cloudflare Caching → Configuration.
  3. Purge the contact URL or purge everything when required.
  4. Use a new private browser window for validation.

8. Verify the complete production flow

  1. Open the contact page in a logged-out private browser window.
  2. Open developer tools, clear the Console, and reload.
  3. Confirm there is no CSP refusal for challenges.cloudflare.com/turnstile/v0/api.js.
  4. Fill every required form field.
  5. Complete the challenge if Turnstile requests interaction.
  6. Submit and confirm the configured success message.
  7. Open AIMF Forms → Submissions and confirm the entry.
  8. Confirm delivery to the notification email.
  9. Open the correct Turnstile widget analytics.
  10. Confirm hostname aimfsecurity.com and action aimf_secure_form.
  11. Confirm Siteverify reports a valid token.
Production validation completed: AIMF Security stored the test submission and Cloudflare populated challenge, hostname, browser, solve-rate, and token-validation analytics.

Safari may report that a Cloudflare iframe cannot directly access the AIMF origin. This is normal same-origin isolation, not a Turnstile CSP failure.

9. YubiKey-encrypted exports

Configuration and submission exports use AES-256-GCM. Each random AES key is wrapped with the RSA-2048 public certificate whose private key remains in YubiKey PIV slot 9D.

ExportContentsExcluded
ConfigurationForms, fields, choices, safe settingsCAPTCHA secrets and submissions
SubmissionsEntries, field data, status, audit metadataNothing is exposed in plaintext

Download

  • Configuration: AIMF Forms → Settings → Download Configuration
  • Submissions: AIMF Forms → Submissions → Download Encrypted Export

Decrypt locally

"/path/to/aimf-secure-contact-form/tools/decrypt-aimf-export.sh" \
  "/path/to/export.ascfenc" \
  "/path/to/decrypted.json"
  1. Insert the authorized YubiKey.
  2. Run the utility locally.
  3. Enter the PIV PIN only at the local prompt.
  4. Use the decrypted JSON only for the approved task.
  5. Securely remove the decrypted copy when finished.
Recovery requirement: if the only YubiKey is lost or damaged, previous exports cannot be decrypted. Maintain an approved backup key or documented recovery strategy before relying on encrypted exports for archival recovery.

10. Troubleshooting

Turnstile analytics is empty

  • Confirm both Turnstile keys are saved.
  • Confirm the correct widget and analytics time range.
  • Submit the form; rendering and Siteverify are different events.
  • Confirm CSP permits Cloudflare in script-src, connect-src, and frame-src.
  • Clear all caches after an update.

Console shows blocked data:text/javascript

  • Disable Autoptimize's Also defer inline JS.
  • Install plugin version 1.1.0 or later.
  • Empty Autoptimize and platform caches.
  • Do not authorize executable data: URLs in CSP.

CAPTCHA verification fails

  • Confirm the site and secret keys belong to the same widget.
  • Confirm aimfsecurity.com is an authorized hostname.
  • Confirm outbound HTTPS access to Cloudflare Siteverify.
  • Remember that the plugin intentionally fails closed during provider errors.

Other console messages

Safari tracker blocking for Google Tag Manager, logged-in Jetpack resources, unrelated /metrics/ errors, and deprecated third-party browser APIs are separate from Turnstile. Validate Turnstile by its API load, iframe creation, successful submission, and Siteverify analytics.

11. Production launch checklist

  • Plugin version 1.1.0 or later is active.
  • Form shortcode references the intended form ID.
  • Required fields and options are correct.
  • Notification email and success message are tested.
  • Turnstile site and secret keys are configured.
  • Hostname is restricted to aimfsecurity.com.
  • CSP permits the exact Turnstile origin.
  • Autoptimize does not defer inline JavaScript as data URLs.
  • Divi and all platform caches are cleared.
  • Private-window submission succeeds.
  • Entry appears in the WordPress backend.
  • Turnstile analytics shows aimf_secure_form.
  • Encrypted configuration backup has been downloaded.
  • YubiKey decryption has been tested.
  • YubiKey recovery strategy is documented.
